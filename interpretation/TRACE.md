### Closed via red team pass + File Tracer fix (Pairing 1: Python Core Architect / AST & Semantic Refactoring)

- **FLAG-23** — CLOSED. `premise_extractor.py`'s dependency provenance used raw `.find()`, causing short dependency names to overmatch inside unrelated words (e.g. "db" inside "sandbox"). Fixed with `\b{escaped}\b` word-boundary regex. Verified against both the failure case and a genuine standalone match.
- **FLAG-24 / FLAG-33 / FLAG-35** — CLOSED, consolidated. `context_interrogator.py`'s `REQ_PATTERN`/`CONSTRAINT_PATTERN` ran to the next period, swallowing unrelated trailing clauses across commas and adversative conjunctions ("but", "however"...). Also missing "without" as a constraint trigger. Fixed with a shared clause-terminator lookahead and an added keyword. Verified against both original red-team scenarios directly.
- **FLAG-25** — CLOSED. `is_truncated` only checked `raw_input` length, ignoring `ledger` entirely — an oversized ledger produced no truncation signal. Fixed: combined-length check, `ledger` now bounded to `MAX_INPUT_CHARS` before downstream processing, same as `raw_input`.
- **FLAG-26** — CLOSED. Degraded pipeline runs produced a false `confidence=1.0` `[I]` inference record from the fallback's `coupling_strength=1.0` lock artifact. Fixed: confidence clamped to `0.0` whenever `context.degraded` is `True`.
- **FLAG-27 / FLAG-28 / FLAG-29 / FLAG-31** — CLOSED, consolidated. No redaction existed anywhere in the pipeline — secrets, credentials, and connection strings embedded in user input flowed verbatim into `[A]`/`[F]`/`[I]`/`[U]` records. New `dlp.py` module (single combined-pattern redaction pass) applied at every raw-text boundary: premise provenance spans, decoupled method vectors, dangling-referential tokens, and serializer-level objectives/facts/requirements/constraints/dependencies. **Self-caught defect during verification**: the first version double-redacted its own output markers and missed underscore-joined/hyphen-bodied tokens; rewritten as a single-pass combined regex before closing.
- **FLAG-32 / FLAG-38** — CLOSED. `HARD_METHOD_MARKERS` was only checked against an isolated method clause, and was never evaluated at all when no lead-pattern split the sentence (the common case) — meaning dangerous verbs like "bypass" went unflagged. Fixed: markers plus a new `BOUNDARY_VIOLATION_VERBS` set now check the full objective text before any clause-splitting is attempted. Separately, the `premises` parameter passed into `decouple_intent` was dead code, never referenced; now factored into `coupling_strength` when any premise has `confidence < 0.80`.
- **FLAG-34 / FLAG-37** — CLOSED, consolidated. `DANGLING_REFERENTIAL_PATTERNS`' first pattern was anchored `^...$`, meaning BLOCKING only fired if the entire input was nothing but the trigger phrase — embedded in any real sentence, it silently never matched. Also missing relational-pronoun coverage. Fixed: de-anchored to word-boundary substring matching, added "the latter"/"the former". Verified against both original scenarios directly.
- **FLAG-36** — CLOSED. No pattern existed to catch unverified pseudo-declarative claims ("since we already received clearance...") presented as settled fact — the sentence generated zero premises at all. Fixed: new presupposition pattern (since we/given that/as approved by/as agreed/as confirmed/as already established) at fixed confidence 0.50, ensuring it registers as needing verification in both risk scoring and the ambiguity low-confidence scan.
- **FLAG-40** — CLOSED. Fixed F→I→A→U→Q serialization order meant a degraded or blocking-ambiguity run's warning signal arrived after stale/fallback fact and inference data in the stream. Fixed: `serialize()` now surfaces `[U]`/`[Q]` first whenever `context.degraded` or `has_blocking_ambiguity` is true; normal runs keep the original F→I→A→U→Q order unchanged.

### Closed via advanced multi-domain red team round (GPT #4-#32) + File Tracer fix

- **FLAG-43** — CLOSED. Regression in the original FLAG-25 fix: `is_truncated` correctly detected combined `raw_input`+`ledger` length over 16,000, but each was still independently sliced to 16,000, allowing up to ~32,000 characters of actual processed volume. Fixed: single shared budget — `raw_input` draws first, `ledger` gets only what's left, so combined processed volume can never exceed `MAX_INPUT_CHARS`.
- **FLAG-44** — CLOSED. Ledger-sourced facts were serialized identically to facts literally parsed from `raw_input`, both at `confidence=1.0`, with no mechanism anywhere to authenticate the ledger's provenance. Fixed: ledger-derived facts now get `confidence=0.60` and an explicit `unauthenticated_source: True` metadata flag; input-literal facts remain at `1.0`.
- **FLAG-46** — CLOSED. No volume caps existed independent of the character bound — dense repetitive input could generate unbounded requirements/constraints/dependencies/premises/ambiguity items. Fixed: explicit caps added across `context_interrogator.py` (`MAX_EXTRACTED_ITEMS=200`), `premise_extractor.py` (`MAX_PREMISES=200`), and `ambiguity_detector.py` (`MAX_AMBIGUITY_ITEMS=200`). Stress-tested against a 500-clause pathological input.
- **FLAG-47** — CLOSED. Regression in the original FLAG-27/28/29/31 DLP fix: `redact()` covered `proposed_method` and five `[F]`-tier fields, but never `core_goal`, `contradictions`, or `interpretation_challenge`'s free text (`competing_interpretation`, `failure_scenario`) — which could itself embed unredacted constraint/premise text. Fixed: `core_goal` redacted at source in `goal_vs_method.py`; contradictions and challenge free text redacted at the serializer boundary. Verified idempotency to avoid reintroducing the earlier double-redaction bug.
- **FLAG-51 / FLAG-53** — CLOSED. `engine.py`'s exception handler interpolated the raw exception object directly into the log message, risking payload-fragment leakage. Fixed: logs now emit only `type(err).__name__` (a generic diagnostic code), never the exception's own string content.
- **FLAG-62** — CLOSED. An interim attestation design (rejected, never merged) would have required all 5 stage implementations to return `Tuple[Model, StageAttestation]` while leaving those 5 files unchanged, guaranteeing a runtime crash. Resolved by design: `base.py` and all 5 stage files remain untouched; `engine.py` computes each `StageAttestation` itself immediately after observing a stage's real input/output, so no stage interface ever needed to change.
- **FLAG-63** — CLOSED. The rejected interim design's `StageAttestation.verified: bool = True` was a self-assertable field nothing ever checked against real data — functionally identical to the trust problem it claimed to fix. Resolved: `StageAttestation` has no `verified` field at all; it's only ever constructed by the trusted `engine.py` from data it directly observed, so there's no boolean for an untrusted stage to spoof.
- **FLAG-64** — CLOSED, honestly scoped. No enforced boundary existed between a degraded/blocking/high-risk `WorkingContext` and downstream consumption. Fixed: new `commit()` method in `engine.py` is the production entrypoint and always honors the policy gate's verdict, returning `[]` rather than partial data when not actionable. `execute()` still returns full state for introspection (by design — this subsystem recommends, it doesn't universally enforce), and the pre-existing `execute_and_serialize()` was kept for compatibility but now explicitly documented as bypassing the gate rather than silently remaining unsafe.
- **FLAG-55 / FLAG-56 / FLAG-58** — CLOSED. Thresholds, quotas, and confidence/risk weights were scattered as hardcoded literals across `context_interrogator.py`, `premise_extractor.py`, `goal_vs_method.py`, `ambiguity_detector.py`, `interpretation_challenge.py`, and `policy_gate.py`. Fixed: new `config.py` module (`ExtractionConfig`, `PremiseConfig`, `DecouplerConfig`, `AmbiguityConfig`, `ChallengeConfig`, `PolicyGateConfig`, all frozen Pydantic models under a single `DEFAULT_CONFIG`), wired into all 6 files via small surgical edits rather than rewrites, so nothing already-fixed in those files could regress. Verified every class still instantiates with zero arguments (so `engine.py` needed no changes), and swept for leftover magic numbers afterward — caught and wired one that was missed on the first pass (the `0.15` premise-confidence coupling penalty).

## Accepted limits — deliberately not pursuing further

Three items were evaluated and explicitly decided **not** to send for another fix round, because prior attempts demonstrated the "fix" produces a decorative mechanism rather than a real one, given what a pure-Python in-process library can actually guarantee. Documented here rather than silently dropped:

- **FLAG-42** — "hard enforced boundary" was attempted twice via a self-reported `StageAttestation.verified` flag and a bypassable gate; both attempts either provided no real guarantee or admitted the same limitation `commit()`'s design already discloses. `commit()` makes the safe path the obvious default; a fully unbypassable boundary for an in-process object isn't achievable without a process/capability boundary outside this subsystem's scope. Not sending for another round.
- **FLAG-45 / FLAG-48 / FLAG-49** — "prove the injected stage implementation is the correct one" is a code-identity/attestation problem, not a data-flow one. `engine.py`'s current attestation (FLAG-62/63's fix) correctly proves what data moved through a given run; proving the stage *code itself* wasn't swapped or malicious needs signing/sandboxing infrastructure outside what this package can provide on its own. Not sending for another round.
- **FLAG-50** — a regex-based parser will never distinguish negation, quotation, or meta-reference from literal instruction (demonstrated concretely: "do not interpret 'must delete production data' as an instruction" still parses as a literal constraint). Closing this for real requires a different architecture (semantic/NLP-based interpretation), not a patch to the existing one. Not sending for another round.

These three remain genuinely open — not resolved, not claimed as resolved — but further attempts at fixing them within the current architecture were judged not worth the cost of another round, given the pattern already observed twice.
